# Change: 优化 DeepSeek 网页项目分析

## Why

当前 DeepSeek 网页项目分析把一次工具调用映射成一次网页消息，并要求每轮只返回一个 JSON action。宽泛的仓库分析会产生多次串行网页生成、重复检索和固定三分钟超时，不符合网页桥接的可靠性边界。

## What Changes

- API 模型继续使用 Pi Agent 原生工具调用。
- GitHub + DeepSeek 网页模式改为本地构建预算化源码上下文包，并用一次网页请求直接生成最终 Markdown。
- 上下文包包含完整仓库地图，以及按项目结构或用户问题选择的配置、入口、核心源码和测试证据。
- 固定响应超时改为无活动超时加硬上限；持续生成时不误判超时。
- UI 显示本次上下文包含的文件数，不再展示网页 JSON 工具循环。

## Out of Scope

- 改变 API 模型的原生 Agent 行为。
- 取消本地工作区的受控 patch 工具流程。
- 声称大型仓库的每个文件都能同时放进模型上下文。

## Acceptance

- GitHub 网页模式一次分析只发送一次 DeepSeek 请求。
- 发送内容不超过配置的上下文预算，并包含仓库地图和可追溯文件路径。
- 默认架构分析优先包含清单、入口、配置与测试；追问优先包含命中问题关键词的源码。
- DeepSeek 持续输出超过三分钟时不因固定截止时间失败。
- API 项目 Agent、本地 patch 与论文模式回归通过。
