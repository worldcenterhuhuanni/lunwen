# 三模式材料分析

## Why

当前产品只能把单篇 PDF 或网页正文作为一个扁平材料发送给模型，无法理解由多个文件组成的软件项目，也无法安全读取和修改用户授权的本地工作区。

## What Changes

- 将入口分为论文、GitHub 项目、本地工作区三种模式
- 保留现有论文 PDF/HTML 提取和模板行为
- GitHub 首版读取公开仓库默认分支，遍历并索引过滤后的全部文本源码
- 本地模式读取用户主动授权的目录，并允许在 diff 审阅确认后写回
- 引入项目 Agent，通过文件列表、文本搜索和按需读文件理解超出模型上下文的项目
- API 模型使用原生工具调用；DeepSeek 网页桥接使用受约束 JSON 协议模拟相同工具循环

## Not

- 首版不访问 GitHub 私有仓库，不提交 commit、PR 或远程写入
- 不读取 `.git`、依赖目录、构建产物、二进制和敏感凭据
- 不把整个仓库一次性拼接进模型提示词
- 不允许 Agent 在未经用户确认时写本地文件
- 不承诺处理超过配置硬上限的无限大仓库

## Impact

- 新增统一材料、源码工作区、IndexedDB、GitHub、本地文件系统和 Agent 模块
- 扩展侧栏、设置页、模板 scope、DeepSeek 桥接与大窗口载荷
- 引入 Pi Agent Core/Pi AI 作为浏览器内 Agent 运行时

## Acceptance

1. 现有 PDF/HTML 论文解读与追问保持可用
2. 输入公开 GitHub 仓库 URL 后可索引默认分支的合规文本源码，并显示文件与排除统计
3. GitHub/API 与 GitHub/DeepSeek 网页两条通路均能搜索并读取多个源码文件后回答
4. 用户可选择本地目录、搜索和分析文件；不支持目录句柄的平台至少可只读导入目录
5. 本地修改必须先展示 diff，且仅在用户确认后写入授权目录
6. 超限、限流、权限撤销、非法工具响应和写入冲突均给出明确错误
